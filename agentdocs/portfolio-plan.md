# 포트폴리오 제작 계획

상태: 1차 구현 완료, 로컬 검증 진행. 공개 배포는 미실행.

## 최신 사용자 지시 및 실행 결과

- 첫 화면은 소개만 표시하고 스크롤하면 프로젝트가 보이게 구현한다.
- 프로젝트를 클릭하면 공통 형식의 정적 상세 페이지로 바로 이동한다.
- JSON 파일 추가로 목록·분류·상세를 자동 생성한다.
- 최신 '작업 시작' 요청에 따라 두 시안 승인 단계는 생략하고 라이트 에디토리얼 방향으로 동작하는 1차 사이트를 구현했다.
- 아래 초기 계획에서 별도 시안 제작과 React/Motion 도입은 필수 단계가 아닌 후보로 변경했다.
- 현재 기준 문서: `implementation.md`, `content-model.md`, `design-system/MASTER.md`, `verification.md`, `deployment.md`.

## 확정된 요구

- GitHub Pages를 사용한다.
- 상단에는 자기소개, 아래에는 프로젝트를 배치한다.
- 고도화된 UI와 시각적 완성도가 가장 중요하다.
- UI UX Pro Max를 저장소 기본 UI 스킬로 적용한다.
- README는 유지하고 작업 문서는 `agentdocs/`에 관리한다.

## 아직 정하지 않은 사항

이름·직무·소개 문장, 공개할 프로젝트와 이미지, 대상 독자, 사이트 언어, 연락처는 확인이 필요하다. 내용이 없는 동안은 임시 데이터로 구도 비교를 진행하되 실제 이력처럼 표현하지 않는다. 기술 구성과 시각적 방향은 아래 제안에서 검토한다.

## 1. 콘텐츠와 구조 설계

- 소개: 이름, 전문 분야, 핵심 한 문장, 짧은 소개, GitHub·연락 링크.
- 대표 프로젝트: 3~6개를 초기 목표로 하되 실제 제공된 수에 맞춘다.
- 프로젝트 데이터: 제목, 한 줄 설명, 역할, 기간, 기술, 썸네일, 저장소·데모 링크, 문제·접근·결과.
- 홈 흐름: 소개 히어로 → 짧은 배경 설명 → 대표 프로젝트 → 기타 프로젝트 → 연락처.
- 프로젝트 상세는 충분한 자료가 있는 경우 별도 정적 페이지로 구성한다.

산출물: `agentdocs/content-model.md`. 필요한 정보와 임시 콘텐츠를 구분한다.

## 2. UI 시안 두 방향 비교

같은 콘텐츠로 데스크톱 첫 화면과 프로젝트 영역을 비교한다. 각 방향에 모바일 축소안을 포함한다.

### A. 다크 에디토리얼

차콜 배경, 따뜻한 흰색, 한 가지 강조색을 후보로 삼는다. 큰 타이포, 넓은 여백, 비대칭 구도와 대형 대표 프로젝트 이미지로 시선을 유도한다. 모션은 스크롤 등장과 짧은 상태 전환을 중심으로 사용한다.

### B. 라이트 갤러리

밝은 배경, 강한 제목 대비, 얇은 구분선, 이미지 중심 구도를 후보로 삼는다. 대표 프로젝트를 크게 배치하고 이후 작업은 크기와 간격에 변화를 준다. 프로젝트 자체의 색감이 살아나도록 주변 장식을 절제한다.

비교 기준: 첫 화면에서 정체성 전달, 프로젝트 발견 용이성, 독창성, 한국어 가독성, 모바일 유지 가능성. 색상과 효과만 바꾼 동일 레이아웃으로 비교하지 않는다.

산출물: `agentdocs/design-directions.md`와 시안. 선택한 방향과 이유를 기록한다.

## 3. 디자인 시스템과 인터랙션

- 의미 기반 색상, 타이포 크기, 간격, 최대 폭, 모서리, 테두리, 모션 토큰을 정의한다.
- 제목과 본문의 한국어·영문 혼용, 행간, 줄바꿈을 실제 문장으로 확인한다.
- 링크·버튼·프로젝트 항목의 기본, hover, focus, active 상태를 설계한다.
- hover에만 숨긴 필수 정보는 두지 않는다. 터치에서도 내용과 링크를 탐색할 수 있게 한다.
- 이미지 확대와 등장 모션은 레이아웃 이동을 만들지 않도록 구현한다.
- reduced-motion에서는 콘텐츠를 읽을 수 있는 최종 상태로 표시한다.
- 3D나 WebGL은 핵심 정체성 표현에 필요할 때만 별도 검토한다.

산출물: `agentdocs/design-system/MASTER.md`.

## 4. 기술 구성 및 구현

제안: Astro + TypeScript, 상호작용이 필요한 곳에만 React/Motion. GitHub Pages에는 정적 빌드 결과를 게시한다. 실제 채택 시 최신 공식 문서와 호환 버전을 확인한다.

- 먼저 홈의 소개와 대표 프로젝트 영역을 완성한다.
- 프로젝트 콘텐츠를 데이터로 분리해 항목 추가와 순서 변경을 쉽게 한다.
- 필요하면 정적 프로젝트 상세 경로를 생성하고 직접 방문·새로고침을 확인한다.
- 이미지 크기와 비율을 예약하고 적절한 반응형 이미지 및 지연 로딩을 적용한다.
- 제목, 설명, 공유 이미지, favicon 등 기본 메타데이터를 준비한다.
- 이메일 링크를 기본 연락 경로로 고려한다. 서버가 필요한 폼은 요구가 있을 때 별도 설계한다.

산출물: 동작하는 사이트와 `agentdocs/implementation.md`의 결정 기록.

## 5. 검증 및 시각적 마감

- 375, 768, 1024, 1440px에서 캡처하고 줄바꿈, 여백, 이미지 크롭, 가로 넘침을 확인한다.
- 키보드 탐색, 포커스 표시, 대비, 모션 감소, 모바일 터치를 검증한다.
- 실제 프로젝트 링크, 이미지 누락, 긴 제목, 콘텐츠 수 변화에 대한 동작을 확인한다.
- 빌드와 타입 검사를 실행하고 브라우저 콘솔 오류를 확인한다.
- 성능은 실제 측정 후 기록한다. 큰 이미지, 폰트 로딩, 불필요한 JavaScript를 우선 조정한다.

산출물: `agentdocs/verification.md`에 실제 결과와 미해결 항목 기록. 자동 검사 성공만으로 시각적 검증을 대신하지 않는다.

## 6. GitHub Pages 배포

- 원격 저장소와 Pages 설정을 확인하고 정적 빌드 워크플로를 구성한다.
- 사이트 빌드 출력만 배포해 스킬·작업 문서가 웹 자산에 포함되지 않도록 한다.
- 배포된 홈, 상세 경로 직접 접근, 이미지·폰트, 모바일 화면을 다시 확인한다.
- 배포 주소와 유지보수 방법을 `agentdocs/deployment.md`에 기록한다.
