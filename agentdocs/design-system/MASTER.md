# Portfolio design system — 구현 1차

## 현재 적용: Connected Cylindrical Navigator (2026-10-16)

사용자는 원통 메뉴 휠 방향이 반대라고 피드백했고, 인접 메뉴를 더 가깝고 분명하게 보이게 하며, 왼쪽에 참고 사이트와 같은 노드·그래프 연결을 요청했다.

- 오른쪽 휠 아래 입력은 이전 메뉴, 위 입력은 다음 메뉴로 이동한다.
- 인접 메뉴는 54도·96px 원통 변환으로 포커스 가까이에 배치하고, 밝기와 크기를 높였다.
- 좌측 SVG 그래프는 메뉴마다 독립적인 노드·간선 구성을 사용하며, 선택 메뉴의 포커스 지점으로 이어지는 밝은 종점을 둔다.
- 최신 사용자 지시에 따라 노드·그래프를 사용한다. 그래프는 접근성 트리에서 제외한 순수 장식이며 메뉴 제어는 여전히 native button으로 제공된다.

## 이전 적용: Focused Cylindrical Menu (2026-10-16)

사용자가 좌측과 우측의 구분선을 지우고 원통 메뉴에는 포커스 메뉴 하나와 인접한 위·아래 메뉴 두 개만 보여 달라고 요청했다.

- 좌우 영역은 별도 배경·경계선 없이 하나의 검은 공간을 공유한다.
- `data-position`이 -1, 0, 1인 세 메뉴만 보인다. 원통 반대편의 -2, 2 메뉴는 숨긴다.
- 포커스 메뉴는 큰 흰색 굵기로, 인접 메뉴는 작은 회색으로 표현한다.

## 이전 적용: Cylindrical Menu / Empty Display (2026-10-16)

사용자는 오른쪽 메뉴가 막대가 아니라 햄스터가 타는 원통처럼 회전하는 메뉴 목록이어야 한다고 정정했다. 따라서 우측 메뉴 레일의 행·구분선·선택 배경을 제거하고, 다섯 텍스트를 세로 원통 표면에 배치했다.

- 선택 메뉴는 원통의 정면에, 이전·다음 메뉴는 위·아래 굴곡에 표시한다. 나머지 항목은 원통 반대편으로 돌아가 보이지 않는다.
- 휠 한 단계와 방향키 한 단계는 72도 회전에 대응하며, 5번 다음은 1번으로 순환한다.
- Main 선택 시 좌측은 비어 있고, 나머지 메뉴 선택 시에만 좌측에 메뉴 이름과 번호가 나타난다.

## 현재 적용: Pannable Graph Canvas (2026-10-16)

사용자가 Jungheon Lee 참고 사이트의 메인 기능을 구현해 달라고 요청해, 원통형 메뉴를 전체 화면 그래프 캔버스로 교체했다. 참고한 것은 공간을 이동하며 연결된 분류를 탐색하는 상호작용이며, 메뉴명·그래프 좌표·코드는 포트폴리오용으로 새로 구성했다.

- 메뉴와 노드·연결선은 같은 1800×1200 월드 좌표계에 놓인다. 화면은 카메라처럼 동작해, 빈 공간을 드래그하거나 휠로 움직이며 그래프를 탐색한다.
- 좌상단 워드마크, 중앙 리티클, 하단 탐색 안내와 월드 좌표 읽기값을 고정해 둔다. Ctrl/Cmd+휠과 `+`/`-`는 중심 기준 확대·축소를 제공하고 화살표 키와 Home은 키보드 탐색을 제공한다.
- 다섯 메뉴는 독립 버튼이다. 선택된 메뉴만 큰 흰색 타입으로 강조하며, 연결망의 밝은 종점과 맞물린다. 세부 콘텐츠가 없는 경력·회사·연락처는 화면에서 꾸며 내지 않고 보조 접근성 패널에서 준비 중임을 알린다.
- 지속 애니메이션을 두지 않고, 메뉴의 짧은 색·크기 전환만 사용한다. `prefers-reduced-motion`에서는 이 전환도 제거한다.

## 현재 적용: Graph Map + Content Panels (2026-10-16)

사용자가 실제 참고 사이트를 다시 직접 테스트한 뒤, 이전의 단순 SVG 탐색기를 교체하도록 요청했다. 홈은 이제 메뉴 라벨을 흩뿌린 그래프가 아니라 각 카테고리의 노드 군집과 실제 콘텐츠 패널을 가진 탐색 지도다.

- 각 카테고리는 허브 라벨, 연결선, 사각형 노드 군집으로 구성된다. 라벨 또는 개별 노드에 hover하면 그 군집의 연결선만 밝게 하고, 클릭하면 해당 콘텐츠를 연다.
- 드래그는 월드를 이동하고, 휠은 포인터 기준으로 카메라 거리를 바꾼다. 화면 하단에는 실제 월드 좌표와 최근 입력 로그를 고정한다.
- 선택된 카테고리는 `?panel=profile`처럼 URL에 남는다. 배경 지도는 작은 blur와 어두운 오버레이로 유지하고, 내용 패널은 220ms 내에 들어온다. 닫기 버튼·Escape·브라우저 뒤로가기는 지도로 복귀한다.
- Profile과 Personal Work에는 제공된 데이터만 표시한다. Career·Company Work·Contact는 내용을 지어내지 않고 준비 중 상태를 표시한다.

## 현재 적용: Profile-Centred Portfolio Map (2026-10-16)

사용자가 고밀도 장식 노드와 전면 오버레이를 거부하고, Profile을 중심으로 실제 포트폴리오 목록만 연결한 그래프를 요청했다.

- 중앙의 Profile에서 Skills, Main Projects, Side Projects, Career, Contact로만 선을 뻗는다. 랜덤 노드, 반복 라벨, 의미 없는 보조선은 사용하지 않는다.
- 모든 노드에는 짧은 hover 설명이 붙는다. 클릭하면 그래프를 유지한 채 오른쪽에서 상세 패널이 열리고, 선택 상태는 `?node=<id>`에 저장된다.
- Profile 패널은 제공된 소개만, Main/Side Projects는 기존 프로젝트 데이터만 사용한다. Skills, Career, Contact는 데이터 준비 상태를 정직하게 표시한다.

- 모든 연결점은 원형 점이며 메뉴 레이블은 점 아래에 둔다. 간선은 점 중심에서 시작·종료하고, 라벨에는 간선을 가리는 배경 여백을 둔다.

## 이전 적용: Right Rail / Empty Display (2026-10-16)

사용자가 메뉴 목록을 오른쪽에 두고, 오른쪽 휠 입력이 왼쪽을 바꾸게 하며, 시작 시 왼쪽에는 아무것도 배치하지 말라고 요청했다. 따라서 검은 화면을 좌측 빈 디스플레이와 우측 메뉴 레일로 단순화했다.

- `MAIN`이 기본 선택 상태다. 이 상태에서 좌측에는 워드마크와 좌표 외의 콘텐츠가 없다.
- 우측 휠, 메뉴 클릭, 방향키로 다음·이전 메뉴를 선택한다. Main 이외의 메뉴는 왼쪽 중앙에 메뉴 이름과 번호만 표시한다.
- 5번 Contact 다음은 1번 Main, 1번 Main 이전은 5번 Contact로 연결한다. 레일 하단에 이전·다음 표기로 이 규칙을 드러낸다.
- 실제 경력·프로젝트 상세나 사진은 이 단계의 화면에 표시하지 않는다. 사용자 요청 전까지 내용은 추가하지 않는다.

## 이전 적용: Spatial Loop Navigator (2026-10-16)

사용자가 Jungheon Lee 참고 사이트와 동일한 검은 무한 캔버스 감각으로 디자인을 다시 요청했다. 최신 요청에 따라 좌측 프로필 레일과 밝은 패널을 제거하고, 전체 화면 검은 탐색 화면으로 구성했다. 이전 요구인 노드 그래프 제외는 그대로 유지한다.

- 구성은 좌상단 워드마크, 중앙 리티클, 화면 가장자리에 분산된 다섯 메뉴 라벨, 하단의 탐색 안내와 좌표다.
- 메뉴 라벨 사이에 선·점·그래프를 그리지 않는다. 선택된 메뉴의 콘텐츠만 중앙에 나타난다.
- wheel, 클릭, 방향키는 Profile → Career → Company Work → Personal Work → Contact → Profile 순서로 순환한다.
- 흑백 대비, 작은 모노 라벨, 큰 활성 텍스트, 포인터 좌표 표시의 공간적 탐색 감각은 참고하되 워드마크·콘텐츠·코드·구체적 배치값은 독자적으로 구성했다.

## 이전 적용: Loop Menu / Portfolio Navigator (2026-10-16)

사용자가 Jungheon Lee 사이트를 참고하되 노드 그래프를 쓰지 않고 5개 메뉴를 마우스 휠로 선택하는 순환 메뉴를 요청했다. 기존 좌측 프로필 레일은 유지하고, 우측을 한 번에 한 메뉴의 내용을 보여 주는 루프 내비게이터로 바꿨다.

- 메뉴는 Profile, Career, Company Work, Personal Work, Contact의 다섯 개다. 마지막 Contact 다음에는 Profile, Profile 이전에는 Contact가 이어진다는 표시를 메뉴 위·아래와 푸터에 둔다.
- 데스크톱에서는 우측 영역 위에서 휠을 내리거나 올리면 각각 다음/이전 메뉴로 이동하고, 배열의 나머지 연산으로 05 → 01과 01 → 05가 연결된다.
- 기본 버튼 탭과 화살표 키도 동일한 루프를 제어한다. 선택된 항목은 `aria-selected`와 해당 `tabpanel`에 반영한다. 650px 이하에서는 가로 메뉴 버튼으로 제공하고 휠 가로채기를 하지 않는다.
- 노드 그래프, 캔버스, 외부 스크립트는 사용하지 않았다. 참고 사이트는 범주 탐색과 `scroll or drag to explore` 안내만 참고했으며, 구조·코드·시각 자산은 새로 만들었다.

## 이전 적용: Profile Rail / Portfolio Index (2026-10-16)

사용자가 직전 전면 픽셀 히어로가 의도와 다르다고 명확히 피드백했다. 홈을 좌측 고정 프로필 레일과 우측 콘텐츠 인덱스로 다시 구성했다. 좌측에는 사진 자리 표시, 이름, 직무, 소개, GitHub와 세 개의 섹션 링크를 모두 둔다. 우측 메뉴와 본문은 경력, 회사 프로젝트, 개인 프로젝트 순서로 이어진다.

- 확인되지 않은 경력·회사 프로젝트를 지어내지 않는다. 두 영역은 `PREPARING` 상태와 이유를 명시한다.
- 제공된 세 프로젝트는 개인 프로젝트 영역에만 두고 기존의 예시 표기를 보존한다.
- 데스크톱은 300–420px 너비의 sticky 레일, 모바일은 상단 프로필 카드와 가로 스크롤 가능한 목차로 전환한다.
- Pixel 아이콘 참고는 좌측의 작은 2×2 마크로만 절제하고, 본문은 목록과 타이포그래피 중심으로 읽힌다.

## 이전 적용: Pixel / Icon Grid (2026-10-16)

사용자가 StreamlineHQ를 활용한 픽셀 아트 감성의 실제 메인 페이지를 요청해, 아래의 Space / Satellite 방향을 교체했다. Streamline의 Pixel 아이콘 계열이 가진 모듈형 기하 도형과 제한된 색상 언어를 시각적 참고로만 사용했다. Streamline의 아이콘 파일이나 브랜드 자산은 포함하지 않았고, 모든 픽셀 도형은 사이트의 CSS로 새로 만들었다.

- 배경 #f4efdf, 잉크 #17232b, 청록 #347c83, 산호 #f36443, 노랑 #f2be4d, 라임 #9db65d를 사용한다. 모든 색상은 의미 토큰으로 `pixel.css`에서 관리한다.
- 제목은 Pixelify Sans, 라벨은 DM Mono, 한국어 본문은 Noto Sans KR 우선의 시스템 대체로 둔다. 한국어 픽셀 폰트 부재로 인한 읽기 저하를 피한다.
- 홈은 소개 → 선택한 작업 → GitHub 연결 순서다. 이름, AI Engineer 직무, 제공된 소개문, 프로필 사진 자리 표시를 첫 화면에 둔다. 실제 사진을 받기 전에는 자리 표시 이미지에 `PHOTO / SOON`을 표시한다.
- 프로젝트 미리보기는 실제 작업 이미지나 외부 아이콘을 가장하지 않는 CSS 도형이다. 기존 프로젝트의 예시 표시는 유지한다.
- 모션은 hover/focus에서 2~4px의 짧은 위치 변화만 사용한다. reduced-motion에서는 스크롤 부드러움과 모든 전환을 중지한다.
- 2px 테두리, 계단식 그림자, 24px 배경 격자로 픽셀 질감을 만들되 내용·링크·포커스 표시가 우선이다.

사용자가 우주와 위성 방향을 제안해 다크 우주 테마로 변경했다. 아래 라이트 에디토리얼 기록보다 이 절이 우선한다.

- 배경 #080d16, 프로젝트 영역 #0e1520, 텍스트 #e9edf3, 보조 텍스트 #9aa8bc, 강조 #b9d4f6.
- 첫 화면에 별·지구 가장자리와 TelePIX BlueBON 지구관측위성의 고해상도 투명 PNG를 배치한다. 제공된 이미지를 바탕으로 위성 구도와 디테일을 유지한 채 검은 배경만 실제 투명 알파로 처리했으며, 화면에 `Satellite image · TelePIX BlueBON` 출처를 표시한다. 자산은 `public/images/telepix-bluebon-hires.png`이며, 배치는 `Satellite.astro`에서 관리한다.

- 소개 문구는 사용자가 제공한 직업과 이름을 반영했다. 프로젝트 3개는 여전히 교체용 예시다.
- GitHub 계정 주소는 기존 espada105를 유지한다. 영문 이름과 계정 변경을 혼동하지 않는다.
- UI 스킬 검색의 히어로 중심·읽기 순서·모션 감소 지침을 채택하고 우주 주제와 맞지 않는 앰버 팔레트는 채택하지 않았다.

## 이전 디자인 기록

사용자 요구: 첫 화면은 소개만, 스크롤 이후 프로젝트, 선택 즉시 공통 상세 페이지. UI UX Pro Max의 포트폴리오 검색 결과에서 여백·비대칭 구성·읽기 순서·접근성 지침을 채택했다. 손글씨 폰트와 무조건적인 즉시 전환은 채택하지 않았다.

## 방향

라이트 에디토리얼을 현재 구현 방향으로 선택했다. 초기 다크 시안 계획은 후보로 보존하지만 별도 시안 승인 단계보다 동작하는 사이트 구현을 요청한 최신 지시를 우선한다. 밝은 종이색과 짙은 녹색, 큰 타이포와 궤도 형태의 CSS 조형으로 첫 화면을 구성한다. 실제 경력 대신 임시 소개임을 표시한다.

- 배경: #f5f3ec, 프로젝트 영역: #eaece4
- 본문: #263d31, 보조 텍스트: #5f6b61
- 구분선: #d5d9ce, 강조: #d0df63
- 제목: Manrope, 강조: Georgia italic, 본문: DM Sans / Noto Sans KR
- 반응형 좌우 여백: 24px에서 100px, 모바일 한 열
- 소개: 헤더 포함 최소 100svh. 프로젝트는 이후 섹션에 배치
- 목록: 첫 프로젝트는 전체 폭, 이후 2열, 모바일 1열
- 모션: 9초의 느린 조형 이동, 짧은 hover 전환. reduced-motion에서는 중지
- 콘텐츠는 애니메이션이나 JavaScript 실행 없이도 읽고 상세로 이동할 수 있음

폰트는 Google Fonts 외부 요청을 사용하고 시스템 폰트 대체 경로를 둔다. 실제 이미지 도입 후 크기·압축과 로딩 전략을 다시 측정한다.
